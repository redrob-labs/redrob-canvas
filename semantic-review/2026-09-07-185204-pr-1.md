# Native Qt/QML editor command and canvas integration

The native shell routes ordinary edits through the Rust JSON command boundary, exposes the advanced command set, snapshots render/layer/selection state by generation, and keeps local and hosted proposals inert until explicit approval. The core schemas, FFI ownership contract, ABI layout tests, native build, and default offscreen smoke capture all pass. Blocking correctness remains around rectangle input conversion, padding, pressure input, proposal replay after a refresh failure, and canvas work that scales with the full zoomed image or selection mask rather than the viewport/change set.

**Watch for:** **confirmed** — numeric rectangle inputs can reach undefined floating-to-integer conversions; **confirmed** — large padding can silently replace the requested padded canvas with an off-origin crop; **confirmed** — selection and checkerboard rendering can perform canvas-scale work on every animated repaint.

**Verdict**: NEEDS_CHANGES

## High-level view

QML/native mutation helpers converge on `EditorBridge::executeCommand`, whose JSON tags and nested objects match `redrob_core::Command`. **Confirmed:** padding composes a valid `crop_canvas` schema with the wrong dimensions when total padding exceeds 32,768, while the shared rectangle builder converts unvalidated `NaN` or out-of-range doubles to `int` before clamping.

Brush gestures commit one command at release, cancellation drops pending points, and rectangle/crop previews preserve signed deltas for negative-drag normalization. **Confirmed:** every collected point still uses pressure `1`, so the native UI cannot exercise the pressure-sensitive core contract.

Render and selection buffers are copied before their Rust allocations are freed, and mixed generations are retried before publication. **Confirmed:** after FFI accepts a command, undo, or redo, a failed refresh is treated as an application failure; proposal application retains the already-executed proposal against the bridge's stale generation and permits resubmission.

**Confirmed:** every refresh republishes and rebuilds the full selection cache, painting the checkerboard iterates the entire zoomed image rather than its visible intersection, and complex masks retain every pixel edge in one animated contour path.

Local and hosted proposals carry generation and document-epoch gates, and the runtime ABI equality guard executes before bridge construction. **Confirmed:** smoke mode does not assert that its selection command changed generation/state, and no CTest/native-QML test registers the gesture, builder, refresh-failure, or canvas behavior.

## Typed command funnel has unsafe rectangle conversion and lossy padding

Layer, selection, brush, gradient, transform, and filter helpers use the exact `redrob_core::Command` field names before entering the one JSON execution overload; undo/redo and document replacement remain explicit separate operations.

**Confirmed:** `rectObject` applies `std::floor`/`std::ceil`, casts the result to `int`, and only then calls `qBound` (`native/qt/EditorBridge.cpp:252-269`). Numeric option fields use `Number(text)`, so invalid text can produce `NaN`, and scientific notation can produce values outside `int`; converting either to `int` is undefined behavior before the clamp can protect the boundary. Validate finiteness and range in floating point, reject invalid input with status, then cast.

**Confirmed:** `padCanvas` independently allows 32,768 pixels on each side and passes the summed size through `rectObject`, which silently clamps width/height to 32,768 (`EditorBridge.cpp:557-566`). On a 1,280-pixel canvas, requesting 32,768 pixels on both horizontal sides creates `x = -32768, width = 32768`; the output is transparent and excludes the source image. Compute target dimensions with checked arithmetic, enforce both the 32,768 dimension and 64-Mpixel core budget, and reject an impossible pad instead of narrowing it.

## Brush gesture commits once but discards tablet pressure

The guarded release path provides one commit, cancellation clears pending points, and signed shape/crop deltas normalize right-to-left and bottom-to-top drags in `rectObject`.

**Confirmed:** initial and subsequent brush samples pass literal pressure `1` (`qml/Main.qml:372,386`). `MouseArea`'s `MouseEvent` does not expose pressure in Qt 6.12, while pointer-handler event points do; use an appropriate pointer/tablet handler and forward clamped pressure to `beginStroke`/`addStrokePoint`, retaining a mouse fallback of 1.

## Snapshot publication can make an executed proposal replayable

`refresh` validates dimensions, stride, length, and generation, deep-copies render and mask data, and frees both FFI buffers on success, failure, or mixed-generation retry. This satisfies `redrob_ffi.h` ownership and prevents mixed-generation publication.

**Confirmed:** `executeCommand` and `executeHistoryAction` return `refresh()` after the FFI operation has already committed (`EditorBridge.cpp:312-348`). `applyProposal` removes the proposal only when that combined return is true (`EditorBridge.cpp:1133-1145`). If refresh fails, the bridge retains its old generation and the proposal remains eligible even though core generation advanced; pressing Apply again executes the command or history action twice. Separate “core mutation committed” from “projection refreshed”: consume the proposal immediately after FFI success, update/gate against the returned change generation, and retry only snapshot publication.

## Selection contour and checkerboard work ignore invalidation and viewport size

**Confirmed:** `refresh` fetches and republishes a full selection snapshot after every command (`EditorBridge.cpp:738-800`), while `CanvasItem::setSelectionMask` always deep-copies it, allocates a 32-bit overlay, scans every mask pixel, and rebuilds the contour (`CanvasItem.cpp:37-43,143-187`). A legal 64-Mpixel document adds a 256-MiB overlay plus full-mask scans even when a brush/filter did not change selection. Consume `ChangeSet.selection_changed` or compare generation/content so the cache changes only for selection/canvas invalidation, and use a shader/tiled overlay rather than another full ARGB image.

**Confirmed:** contour extraction emits up to four path segments for each nonzero pixel boundary and the ants timer redraws the entire path every 140 ms. A valid imported checkerboard mask can produce hundreds of millions of segments. Bound contour complexity using marching-squares/run-length contours, tile or downsample at low zoom, and animate only visible geometry.

**Confirmed:** checkerboard painting loops from the zoomed image's left/top to `target.right()/bottom()` (`CanvasItem.cpp:236-242`) despite the item clip. The default 1,280×800 image at 32× zoom causes roughly 3.5 million `fillRect` calls per repaint for a ~1,000×800 viewport. Intersect `target` with the exposed/item clip before deriving tile bounds.

## Proposal gates are sound, but smoke success does not validate them

Local proposals snapshot bridge generation/epoch; hosted proposals carry the FFI snapshot generation and request epoch. Applying either checks both before mutation, so edits or document replacement while a request is in flight fail closed.

**Confirmed:** smoke mode ignores the return/state of `selectEllipse` and exits successfully whenever a root object exists and an optional screenshot can be saved (`native/qt/main.cpp:38-57`). The offscreen run produced a 1,440×900 image with the ellipse overlay, but a command-schema, mask-copy, or generation regression could still return success with an unchanged canvas. Assert generation increment, `selectionActive`, mask dimensions/content, and window size before success, and register the smoke path plus focused native/QML tests with CTest.
