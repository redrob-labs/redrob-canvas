# Hierarchical groups and raster masks across core, agent, FFI, and Qt

The change adds canonical post-order layer groups, raster and group masks, recursive isolated compositing, hierarchy/mask commands, agent tools, additive FFI summaries, and a top-first Qt/QML projection. Core mutation remains transactional, ChangeSet classifications match the affected structure/layers/canvas/selection, and canvas transforms cover all cels, masks, and selection state. The basic native hierarchy/mask smoke path and all Rust checks pass. **Watch for: confirmed, high severity — valid wide group trees can amplify one render into hundreds of gigabytes or more of buffer clearing/compositing; confirmed, medium severity — agent proposals accept add/move destinations that necessarily exceed the hierarchy-depth limit; confirmed, medium severity — the normal QML UI can attach masks but cannot author mask coverage, and raster-only Options actions remain enabled for groups.**

**Verdict**: NEEDS_CHANGES

## High-level view

The core stores nodes in bottom-to-top post-order, rebuilds that order after insert and move, and rejects noncanonical serialized trees. Add/move/delete operations are transactional, with cycles, non-group parents, nonempty group deletion, and invalid sibling indices rejected before publication; same-parent indices use the post-removal sibling list.

Recursive rendering isolates each group, then applies its mask, opacity, and blend once at the parent boundary. Peak intermediate storage is depth-preflighted, but **confirmed, high severity:** aggregate work across wide trees is not bounded, so thousands of sibling groups can each clear and composite a full-canvas intermediate.

Agent declarations are closed schemas and proposals validate IDs, parents, cycles, sibling counts, mask state, and raster capability. **Confirmed, medium severity:** destination depth is not calculated for either new groups or moved subtrees, so proposals can be generated that core will reject when applied.

FFI emits versioned node summaries with parent, depth, kind, group child count, mask state, and capability data. Qt reverses canonical core order into group-first, top-first presentation while retaining core indices and bottom-to-top sibling indices.

The QML layer menu exposes hierarchy movement and mask lifecycle operations. **Confirmed, medium severity:** masks created there are always white and no QML action calls the coverage replacement path; **confirmed, medium severity:** raster-only filter/transform/clear controls in Options are not gated when a group is active. **Confirmed, low severity:** top-boundary and parented reorder controls remain available when they can only fail.

## Canonical post-order hierarchy and transactional mutation

`insert_node` and `move_node` rebuild sibling lists through recursive post-order, keeping every subtree contiguous and every group after its descendants; load validation independently reconstructs and compares canonical order (`crates/redrob-core/src/document.rs:788-873, 1480-1551, 1637-1684`). Moves remove the source before insertion, so same-parent destinations `0..=N-1` are final sibling indices. Parent/type/cycle/depth failures remain inside the cloned transaction candidate.

Nonempty group deletion returns `NonEmptyGroup`. Deleting an active leaf selects the node at the removed canonical slot or the preceding final node, yielding a higher sibling, containing group, or preceding node depending on position. Hierarchy commands set `structure_changed` and identify the moved/added/deleted node plus affected parents; mask commands identify their target; crop/resize mark canvas and selection invalidation and every node.

## Wide group trees have bounded peak memory but unbounded render work

**Confirmed, high severity:** every visible group allocates, zeroes, and composites a full-canvas intermediate (`crates/redrob-core/src/render.rs:35-36, 60-70`). `try_render` bounds only simultaneously live buffers as `pixel_bytes * (maximum group depth + 1)` (`render.rs:100-116`). A valid depth-zero tree may contain up to 4,096 groups and a canvas up to 64 Mi pixels (`document.rs:16-19, 29-40`) while passing the two-buffer peak check, forcing hundreds of gigabytes at ordinary 4K sizes and over a terabyte at the model limit before one frame completes.

Preflight visible raster/group pixel visits with checked arithmetic and a documented render-work ceiling, or use bounded/tiled intermediates. Add a valid wide-tree regression that fails before the first intermediate allocation.

## Group compositing and mask alpha application

Raster masks multiply source alpha by 8-bit coverage before opacity/blend; disabled masks are filtered out. Groups flatten children into transparent storage and apply their mask, opacity, and blend only at the parent boundary. Crop and resize iterate every node mask and every cel, with aggregate target storage preflighted before mutation (`document.rs:1248-1356`).

## Proposal depth validation does not match core hierarchy limits

**Confirmed, medium severity:** `ProposalContext` records current depth, but `add_group` checks only parent type and sibling bounds (`crates/redrob-ffi/src/graphics_tools.rs:1548-1574`). `move_node` checks cycles and the post-removal sibling count, then tests `node.depth > MAX_HIERARCHY_DEPTH` (`graphics_tools.rs:1576-1624`). Contexts come from validated documents, so that condition cannot catch a bad destination and ignores subtree height. Adding below a depth-256 group or moving a nested subtree under a deep group therefore produces a proposal that deterministically fails at apply.

Replace it with `destination_depth + subtree_height <= MAX_HIERARCHY_DEPTH`, apply destination validation to `add_group`, and test exact-limit, one-over, and moved-subtree cases.

## Mask authoring and raster gating stop at the presentation layer

**Confirmed, medium severity:** QML can add, toggle, and remove a mask (`qml/Main.qml:596-614`), but no QML code invokes `EditorBridge::replaceRasterMask`; only native smoke does (`native/qt/EditorBridge.cpp:557-588`, `native/qt/main.cpp:29-39`). Since a new mask is all white, normal UI cannot make it affect output. Add a bounded typed mask-from-selection command or transactional mask-editing mode, then exercise the production QML action in smoke.

**Confirmed, medium severity:** toolbar tools and pointer input require a raster active node (`qml/Main.qml:232-268, 385-388`), but Options buttons for flip, rotate, affine transform, filters, and clear remain enabled for groups (`qml/Main.qml:1080-1280`). Bind all raster-only actions to a shared active-node capability and smoke-assert the disabled state.

**Confirmed, low severity:** “Move toward top” always submits `siblingIndex + 1` (`qml/Main.qml:584-593`), so the top sibling sends destination `N` after source removal, where the maximum is `N-1`. The root-only legacy Reorder control also remains visible for parented nodes (`qml/Main.qml:1280-1294`). Expose sibling count/top state and disable or replace these invalid actions.

## Regression coverage and feature-status drift

**Confirmed, low severity:** native smoke covers one group-before-child mapping, an enabled group mask’s render effect, and undo restoration (`native/qt/main.cpp:29-65`), but not same-parent top/bottom movement, proposal depth rejection, disabled-mask Qt projection, raster-control gating, or QML-authored coverage. Add focused core/agent boundary cases and production-QML assertions.

**Confirmed, low severity:** `docs/compatibility.md:9` combines groups, masks, and pass-through projection as planned, while architecture and code implement the first two and explicitly reject pass-through. Split the status row.

Verification passed: `cargo test --workspace` (92 tests plus doc tests), `cargo clippy --workspace --all-targets -- -D warnings`, the Qt 6.12 build, and registered offscreen `redrob_native_smoke`. Qt configuration warned about unavailable optional `Qt6TaskTree` through `QmlAssetDownloaderPrivate`; generation, compilation, and smoke still succeeded.
