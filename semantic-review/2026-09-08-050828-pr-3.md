The follow-up closes the three remaining resource-admission gaps while preserving the previously repaired vector/text behavior. Project decoding now limits v1/v2 node arrays and charges semantic totals as paths and nodes are admitted, hosted semantic proposals use the core’s candidate-document transaction as their applicability check, and fill-plus-stroke vectors charge both edge traversals. ## High-level view

Version 2 decoding charges vector-wide usage before retaining each path and document-wide text, path, command, and semantic-memory usage before retaining each node. Version 1 independently stops its layer sequence at the same 4,096-node ceiling and skips the first excess element without typed deserialization.

Vector work admission now charges one sample-edge traversal per enabled paint branch. Full-canvas exact boundaries are 16 edges for fill-only or stroke-only and eight edges for fill-plus-stroke.

The earlier grammar, paintless-path, transactional recovery, source-preserving Qt edit, compositing, and font-notice repairs remain covered. Full Rust and native validation passed.

## Decode visitors enforce aggregate semantic budgets before document retention

`VectorContent` ignores untrusted size hints, caps its path array, and accumulates each decoded path’s command count and modeled memory before retaining it. `Document.nodes` applies the shared `semantic_usage` and `admit_semantic_replacement` contract before retaining each typed layer. Individually legal paths or nodes can therefore leave at most the currently decoded bounded element transiently allocated when an aggregate limit rejects them, rather than a complete over-budget document.

Exact/one-over regressions cover the 4,096-node v2 array, the independent 4,096-layer v1 wire array, one million commands across 16 paths, one MiB of text across four nodes, and 4,096 paths across four vector nodes. Untyped excess-node fixtures verify both node visitors skip rather than deserialize the first over-limit entry.

## Semantic proposals share the authoritative candidate transaction

The five semantic command variants execute against a disposable `Editor` created from the request’s private document clone. That invokes the same candidate semantic, render-topology, and stored-raster validation as live Apply without changing the live document, generation, or history. The native queue later compares both the captured generation and document epoch before executing the returned command.

An off-canvas AddText is accepted at the exact 256 Mi render-visit topology and rejected one group over; Rasterize is accepted when exactly one current-frame cel remains under the one GiB storage ceiling and rejected when it would exceed it. The fixtures also apply every semantic proposal to its authoritative snapshot and preserve deterministic collision probing.

## Private admission snapshots do not widen hosted context

`ProposalContext` owns the document required for dry-run parity but is neither serializable nor included in `agent_system_prompt`. The production request uses `agent_layers_value`, where text is represented by counts and style/origin metadata; local `layers_value` separately carries source text and previews. A production-builder regression verifies a sentinel remains local and absent from the hosted system message.

Freshness remains independent of admission: playback and edits advance generation, and Apply checks both generation and document epoch after stopping playback.

## Dual-paint work matches the rasterizer’s worst-case traversal

`prepare_vector` multiplies clipped pixels, the 4×4 sample grid, and edge count by the number of enabled paint branches using checked arithmetic. This bounds the rasterizer’s separate winding and stroke-distance scans; paintless paths remain typed style rejections.

The full-canvas boundary fixture accepts 16 and rejects 17 edges for each single-paint case, then accepts eight and rejects nine for fill-plus-stroke. Rejections preserve document, generation, and history.

## Original vector/text findings remain closed

Filled open subpaths close at `MoveTo` and path end, post-`Close` drawing requires a new `MoveTo`, stationary segments are no-ops, and paintless paths reject. Add and Set validate complete candidates before generation/history commit, while Qt permits Undo through a stale projection.

Qt retains full text source and editable style/origin fields; rectangle editing is advertised only for canonical two-paint shapes the replacement command reproduces losslessly. Semantic-before/raster-after output remains equivalent over opaque nested backdrops across blend modes.

The exact font8x8 notice remains installed with the application. Temporary-prefix SHA-256 checks confirmed both installed license files match their sources.
