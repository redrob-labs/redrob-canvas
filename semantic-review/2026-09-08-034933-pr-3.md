# Deterministic native text and vector editing path

Task #3 adds editable text and vector nodes rendered entirely by the Rust core, then carries them through commands, history, Agent proposals, FFI projections, and Qt production controls. A pinned bitmap font, 1/256-pixel geometry, fixed cubic subdivision, and 4×4 coverage grid define the reproducible raster contract; rasterization targets only the current frame while retaining node identity and compositing properties. The implementation is not ready to ship because accepted paths can paint the wrong region, valid edits can make the Qt shell unrecoverable, native edit dialogs overwrite properties they never loaded, and semantic text crosses the hosted-Agent boundary. Resource admission and third-party notice delivery also have blocking gaps.

**Watch for:** **[HIGH, confirmed]** open filled subpaths omit their closing edge and post-`Close` grammar is inconsistent; **[HIGH, confirmed]** Add/Set can commit content that rendering rejects, after which Qt blocks Undo and edits; **[HIGH, confirmed]** the hosted-Agent prompt contains raw text previews; **[HIGH, confirmed]** project loading allocates semantic payloads before enforcing smaller model limits; **[HIGH, confirmed]** text editing replaces unprojected origin/size/color values; **[HIGH, confirmed]** installed binaries omit the required font8x8 MIT notice.

**Verdict**: NEEDS_CHANGES

## High-level view

Geometry and glyphs stay in a bounded, platform-independent raster path. Path closure is unresolved: fill evaluation consumes only emitted edges while validation accepts open contours, so accepted data can rasterize a different region than authored.

Semantic nodes pass through the existing isolated temporary/composite boundary, preserving node opacity and blend exactly once. Add/Set admit canvas-dependent work only at render time, however; a render-limit error makes Qt mark its projection stale and disable the Undo/edit paths needed for recovery.

FFI v2 capabilities are additive and generation-coherent, but production dialogs do not retain authoritative semantic source values. Agent proposals also omit document-wide semantic totals and deterministic-ID collision checks.

Validated documents have semantic count limits, but serde materializes the complete project first under a 5.5 GiB envelope. Paintless paths still consume raster work, and raw text previews are reused as hosted-Agent context despite the documented summary-only boundary.

The font crate version and checksum are pinned, but the full MIT notice is neither present in the distribution notice nor installed with the executable.

<summary>Details</summary>

## Open contours and `Close` do not define a coherent fill grammar

**[HIGH, confirmed]** `validate_path` accepts a filled subpath ending without `Close`, while `flatten` emits no edge from its last point to its start (`crates/redrob-core/src/semantic.rs:73-139`, `:331-390`). `point_in_path` computes winding from that incomplete set. For `M(0,0) L(10,0) L(10,10)`, the missing diagonal makes samples left of the diagonal follow the vertical edge alone; within vertex bounds the result behaves like a rectangle rather than the authored triangle. Multiple open subpaths fail independently. Append an implicit closure for every filled subpath—including before a new `MoveTo` and at path end—or reject fills unless every non-empty subpath is explicitly closed.

**[HIGH, confirmed]** Validation and flattening leave `current` at the start after `Close` but clear `start`: a following `LineTo` is accepted, while a later `Close` is rejected because its start was forgotten. A contour that explicitly returns to its start and then closes is also rejected, although zero-length `LineTo` edges are accepted and stroked as round disks. Preserve the subpath start if post-close segments are legal, or require a new `MoveTo`, and define zero-length behavior consistently.

## Paintless paths consume work and can poison rendering

**[MEDIUM, confirmed]** `VectorPath` permits both paint fields to be absent. `prepare_vector` still flattens it and charges `pixels × 16 × edges`; `rasterize_vector` still visits each bounded sample although no branch can write output (`crates/redrob-core/src/semantic.rs:283-328`, `:445-497`). A large paintless contour can return `SemanticWorkLimitExceeded` or perform a large empty scan. Reject paintless paths or omit them before segment/work accounting and raster loops; an intentionally empty `VectorContent` can remain a cheap transparent state.

## Render-limit failures leave the Qt application unrecoverable

**[HIGH, confirmed]** core Add/Set methods call style/grammar validation rather than canvas-dependent preflight (`crates/redrob-core/src/document.rs:1143-1208`). The tests demonstrate a vector command that commits and only later fails rendering with `SemanticWorkLimitExceeded` (`crates/redrob-core/tests/semantic_path.rs:261-300`).

After that commit, `EditorBridge::refresh` fails at `redrob_editor_render_rgba`; retry marks the projection stale, while `executeCommand`, history, navigation, and open paths refuse activity in that state (`native/qt/EditorBridge.cpp:392-434`, `:540-543`, `:1191-1329`). Retrying the same render cannot recover. Preflight Add/Set against the current canvas in production paths, and allow Undo/open/delete recovery for committed states whose render projection failed.

## Native “Edit text” replaces values that were never loaded

**[HIGH, confirmed]** FFI projects text origin, size, color, family, and font ID, but `LayerModel` retains only preview/truncation and vector counts (`crates/redrob-ffi/src/abi.rs:180-238`, `native/qt/LayerModel.cpp:85-132`). The text action copies only `semanticPreview`; X, Y, and Size stay at dialog defaults and acceptance uses the current brush color (`qml/Main.qml:672-710`, `:887-899`). Editing one character can therefore move, resize, and recolor the node; the populated name field is ignored by Set.

Project the authoritative fields into model roles or fetch an immutable node DTO when the dialog opens. Initialize every editable control from that source and either remove the name field or issue an explicit rename. Rectangle controls need the same contract for native rectangles; arbitrary vectors should be labeled as replacement unless their geometry can be reconstructed.

## Hosted Agent context crosses the documented text boundary

**[HIGH, confirmed]** `semantic_node_value` copies the first 256 text characters into each layer DTO, and `agent_system_prompt` serializes all layers into the hosted request (`crates/redrob-ffi/src/abi.rs:180-200`, `:386-416`). Bounded raw content is still raw content and contradicts `docs/architecture.md`’s summary-not-secrets boundary. Confidential text is transmitted without content-specific consent.

Remove previews from network context by default and send counts/style/capabilities only, or require explicit disclosed inclusion with redaction. Keep local LayerModel previews separate and test the exact outbound system message.

## Project and command admission do not bound semantic memory at allocation time

**[HIGH, confirmed]** `load_project` permits `MAX_STORED_RASTER_BYTES * 5 + 512 MiB` and deserializes the full `Document` before validation applies the 1 MiB aggregate text and one-million-command limits (`crates/redrob-core/src/codec.rs:15-18`, `:92-112`; `crates/redrob-core/src/document.rs:2288-2359`). A multi-gigabyte string or command array can be allocated before rejection.

Use bounded custom deserializers/streaming visitors or a tighter, structurally justified envelope. Add an aggregate semantic-memory budget as well: command execution deep-clones strings and path vectors through `before`, `after`, conversion, and history snapshots, so a maximum valid vector has several simultaneous heap copies before history accounting can evict it.

## Agent proposal validation can approve actions that cannot apply

**[MEDIUM, confirmed]** semantic tool decoding is strict and preflights per-payload work, but `ProposalContext` has no aggregate text-byte/path/command totals. Add/Set can pass proposal validation and then exceed document-wide limits on Apply (`crates/redrob-ffi/src/graphics_tools.rs:1180-1260`, `:1982-1989`, `:2280-2430`). Add IDs depend only on tool name and call ID and are not checked against existing nodes, so a repeated provider call ID in a later request creates a fresh-generation proposal that fails with `DuplicateNodeId`.

Carry aggregate counters in `ProposalContext`, subtract replaced content for Set, and reuse core admission arithmetic. Probe deterministic IDs against immutable context as frame IDs already do.

## font8x8 notice is pinned but not delivered with binaries

**[HIGH, confirmed]** `font8x8 = "=0.3.1"` and the lockfile checksum match `THIRD_PARTY_NOTICES.md`. The notice only paraphrases and links the MIT terms, while `native/qt/CMakeLists.txt` installs only the application target. Installed binaries therefore do not retain the upstream notice the repository says must accompany them.

Include the exact upstream MIT copyright/permission text, verify it against the pinned source, and package `LICENSE` plus `THIRD_PARTY_NOTICES.md` with every binary. Keep bitmap public-domain provenance separate from wrapper-license obligations.

## Coverage does not exercise the failure boundaries above

**[LOW, confirmed]** goldens cover one closed rectangle and one closed cubic; rasterize equivalence uses a transparent backdrop. Tests omit open/multiple subpaths, segments after `Close`, explicit return-to-start plus `Close`, zero-length edges, paintless paths, fill-then-stroke ordering, rasterize quota boundaries, and blend equivalence over an opaque lower layer/nested groups. Native smoke omits editing a non-default text node and recovery after a typed render failure.

Add fixtures after specifying the grammar. Compare semantic-before/raster-after output over an opaque backdrop for every blend mode and non-unit opacity, preserve selection bytes, exercise current-frame-only behavior in nested groups, and verify native recovery from an over-budget edit.
