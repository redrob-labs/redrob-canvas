# Bounded semantic editing and native recovery hardening

The implementation closes most of the nine earlier findings by unifying path validation and flattening, rejecting paintless paths, preflighting full documents before commit, separating hosted-Agent metadata from local text projection, and carrying authoritative semantic fields into Qt. It also introduces bounded semantic decoding, aggregate proposal admission, deterministic ID probing, exact font licensing text, install rules, and broader core/FFI/native fixtures. Two behavioral contracts remain incomplete: public in-memory core commands can still create semantic payloads that the project decoder refuses, and Qt rectangle editing cannot preserve canonical rectangles with only one paint style. The requested validation gate also does not currently pass.

**Watch for:** **[HIGH, confirmed]** direct Rust `Command` execution bypasses the documented 256 KiB text, 256/128-byte font, 4,096-path, and 65,536-command-per-path limits; **[MEDIUM, confirmed]** fill-only or stroke-only canonical rectangles are advertised as editable but the Qt editor always reconstructs both paints; **[MEDIUM, confirmed]** required production-boundary fixtures remain absent; **[MEDIUM, confirmed]** formatting and whitespace checks fail.

**Verdict**: NEEDS_CHANGES

## High-level view

Semantic commits now validate the candidate document before generation/history changes, including canvas-dependent semantic work and aggregate render work. Full validation applies aggregate limits but not every per-payload limit enforced by serde, so valid in-memory state can become unloadable after a save.

Qt retains text origin, size, color, font metadata, and recognized rectangle geometry through local projection. Rectangle recognition accepts optional fill and stroke, while the native edit command has no representation for either paint being absent, leaving a subset of recognized source data non-editable without changing its semantics.

The expanded suite covers grammar, privacy, aggregate proposal arithmetic, opaque compositing, source projection, and stale Undo/Open recovery. It omits several explicitly requested production boundaries, and the final formatting gate reports concrete failures.

## Core semantic admission differs between typed commands and project decoding

**[HIGH, confirmed]** `TextContent` and vector array limits are enforced only by custom serde visitors (`crates/redrob-core/src/document.rs:38-99`, `:461-538`). `validate_text` checks font identity, style, coordinates, and glyph support but not text/font byte lengths; `validate_vector` delegates to path grammar without checking `MAX_VECTOR_PATHS` or `MAX_PATH_COMMANDS_PER_PATH` (`crates/redrob-core/src/semantic.rs:52-84`). Document admission checks only the 1 MiB aggregate text total, 4,096 aggregate paths, one-million aggregate commands, and 64 MiB aggregate logical memory.

A public typed Rust caller can execute an off-canvas 300 KiB text command, or a vector with one 65,537-command path, and commit/save it because both remain below aggregate limits. Loading the saved project rejects the same payload during deserialization. Move the per-field and per-path checks into reusable core validation called by both serde and command/document admission, and add direct `Editor::execute` plus save/load round-trip regressions at exact and one-over boundaries.

## Recognized rectangle editing cannot represent optional paints

**[MEDIUM, confirmed]** the FFI recognizer accepts a canonical rectangle whenever its single path has the expected five commands, regardless of whether fill or stroke is absent, and publishes `has_fill`/`has_stroke` (`crates/redrob-ffi/src/abi.rs:182-211`). `LayerModel` does not retain those flags, while QML enables editing for every recognized rectangle and `EditorBridge::rectangleVector` always emits both a fill and a positive-width stroke (`native/qt/LayerModel.cpp:139-181`, `native/qt/EditorBridge.cpp:774-831`, `qml/Main.qml:958-980`). A fill-only rectangle opens with an empty stroke source and cannot be accepted unchanged; supplying values changes it into a fill-and-stroke rectangle. The same asymmetry applies to stroke-only rectangles.

Preserve style presence as authoritative roles and model data, let the edit command emit `null` for an absent paint, and test fill-only, stroke-only, and fill-plus-stroke round trips through the QML/native production action. Alternatively, narrow recognition/edit capability to the style shape the editor can losslessly reconstruct. **[LOW, confirmed]** the requested LayerModel source invokables are also absent; only roles were added, so add immutable source accessors or explicitly revise the API contract.

## Required boundary fixtures do not cover every production path

**[MEDIUM, confirmed]** the suite has no rasterize storage-quota exact/one-over fixture, no direct in-memory command regression for the serde-only limits above, and no load fixture proving a hidden over-work semantic node is rejected. Canvas-work transaction coverage exercises `AddVectorNode`, but not over-budget `AddTextNode`, `SetTextContent`, `SetVectorContent`, and `RasterizeSemanticNode` individually. Aggregate semantic-memory exact/one-over coverage constructs `SemanticUsage` directly rather than decoding or committing many real nodes, and the native source test covers only a rectangle with both paints.

Add production-path tests for those boundaries rather than relying on helper-level arithmetic. Preserve the existing open-contour, paintless, Agent sentinel, proposal collision, opaque blend, fill/stroke ordering, selection/current-frame, and stale recovery fixtures.

## Requested formatting and whitespace gates fail

**[MEDIUM, confirmed]** `cargo fmt --all -- --check` reports an unformatted assertion in `crates/redrob-ffi/src/abi.rs:1156-1159`. Because every repository file is untracked, plain `git diff --check` is vacuous; applying the same check to the untracked files reports a blank line at EOF in `crates/redrob-ffi/Cargo.toml:21`. Format the Rust workspace, remove the trailing blank line, and run an untracked-aware whitespace check until the repository has a baseline commit.
