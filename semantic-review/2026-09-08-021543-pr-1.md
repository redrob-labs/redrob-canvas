## Agent Apply is ungrouped, but the history claim includes undo and redo

`redrob_agent_propose` snapshots state and returns proposals without executing commands. `EditorBridge::applyProposal` requires the queued generation and document epoch to match, then applies exactly one `command`, `undo`, or `redo`; no Agent path calls `begin_group` or `end_group` (`crates/redrob-ffi/src/abi.rs:443-505`; `native/qt/EditorBridge.cpp:1330-1413`). Command proposals pass through `executeCommand`, `redrob_editor_execute_json`, and `Editor::execute`, whose ungrouped `History::record` creates one undo entry (`native/qt/EditorBridge.cpp:360-401`; `crates/redrob-ffi/src/abi.rs:509-533`; `crates/redrob-core/src/editor.rs:160-180, 448-469`).

**Confirmed, low severity:** Agent declarations and proposal conversion explicitly support `undo` and `redo`, and production routes them to `redrob_editor_undo`/`redrob_editor_redo` (`crates/redrob-ffi/src/graphics_tools.rs:499-502, 2076-2122`; `native/qt/EditorBridge.cpp:390-430, 1397-1406`). Core moves an existing entry between undo and redo stacks; neither action creates a new entry (`crates/redrob-core/src/editor.rs:487-518`). `docs/architecture.md:17` is therefore not exact when it says every applied proposal “creates its own history entry,” and `docs/compatibility.md:24` leaves the same ambiguity with “separate history entries.” Qualify the claim as successful command proposals creating separate entries and approved undo/redo proposals navigating history.

## Render work and hierarchy destinations remain bounded at their behavioral limits

The renderer derives work from visible raster composites and isolated-group clear/composite operations, multiplies it by canvas pixels with checked arithmetic, and rejects work above `MAX_RENDER_PIXEL_VISITS` before output or intermediate allocation (`crates/redrob-core/src/render.rs:28-86, 159-187`). The 1,024² wide-tree regression accepts exactly 256 Mi pixel visits and rejects the first group over the limit (`crates/redrob-core/tests/editor_core.rs:1622-1652`).

Agent `ProposalContext` derives destination depth from the validated parent and subtree height from descendants. Add-group and move-node conversion reject one-over-limit destinations while retaining exact-limit leaf and subtree moves (`crates/redrob-ffi/src/graphics_tools.rs:1022-1048, 1594-1667, 3129-3227`). Core independently validates hierarchy transactionally, and same-parent movement retains exact top/bottom and first-invalid-index coverage.

## Selection-authored masks and shared UI capabilities remain connected

`RasterMaskFromSelection` rejects inactive selection without publishing state, copies full-canvas 8-bit coverage into a new or existing enabled raster/group mask, and participates in normal history (`crates/redrob-core/src/document.rs:938-963`; `crates/redrob-core/tests/editor_core.rs:1990-2052`). Agent conversion validates mask capability and active selection; the ABI regression verifies summaries, mask state, and output. Production QML calls `editor.rasterMaskFromSelection` through `maskNodeFromSelection`, closing the former all-white-mask dead end (`qml/Main.qml:35-37, 608-613`).

FFI reports `can_edit_raster` only for raster nodes and `supports_pass_through: false`. `LayerModel` projects that capability plus sibling boundaries, and QML disables raster-only actions for groups while bounding sibling moves and omitting the old parent-invalid reorder route (`crates/redrob-ffi/src/abi.rs:179-203`; `native/qt/LayerModel.cpp:34-102`; `qml/Main.qml:232-277, 560-620, 1005-1351`). Native smoke invokes the production QML mask function and checks masked rendering, disabled-mask behavior, raster/group action state, and undo restoration (`native/qt/main.cpp:27-126`).

## Regressions still exercise the seven repaired gaps

`cargo test --workspace` passes all 98 Rust tests and doc tests, including wide-render work, exact hierarchy depth, same-parent movement, mask transactionality, isolated group compositing, Agent destination depth, and ABI hierarchy/mask projection. `cargo clippy --workspace --all-targets -- -D warnings` passes. The Qt build and both production-QML smoke tests, `redrob_native_smoke` and `redrob_minimal_platform_smoke`, pass.

The compatibility matrix still marks isolated groups and raster masks native and pass-through projection separately planned (`docs/compatibility.md:8-10`); architecture still states that pass-through has no command or serialized state.
