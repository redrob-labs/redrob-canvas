# Bounded graphics editor with two atomicity and source-integrity gaps

The initial implementation establishes a transactional Rust document/editor core, bounded RRG and interchange formats, an ABI-v2 C boundary, a Qt Quick shell, inert generation-bound agent proposals, and release-gated compliance artifacts. The four prior findings are addressed: ORA requires one correctly nested image/root stack, failed Qt imports no longer stop playback before validation, adversarial parser tests assert the intended typed boundaries, and installation includes generated complete notices plus corresponding source. The latest source-identity split keeps tracked `SOURCE_OFFER.md` independent of Git state while each generated bundle records its generation-time branch, commit, configured public origin, and declared repository. Two release-relevant gaps remain: rejected Qt actions can still mutate playback, and cached registry source bytes are copied without being tied back to the checksum-verified crate archive.

**Watch for:** **confirmed** — Qt stops playback before command/history/proposal success is established, making rejected actions state-changing and self-invalidating a current proposal applied during playback; **confirmed** — the source generator verifies each cached `.crate` checksum but copies a separate unpacked source directory without verifying that directory against the archive.

**Verdict**: NEEDS_CHANGES

## High-level view

The Rust core uses detached candidates for command execution and imports, validates complete document invariants before replacement, and bounds semantic work, render work, history, raster storage, format bytes, XML, and archive expansion. Format routing is content-based, and explicit-frame exports remain nonmutating.

ORA now rejects sibling, cross-nested, duplicate, or trailing image/root structures. SVG security fixtures contain otherwise valid supported content, and ORA unit fixtures reach exact/one-over entry, byte, XML, hierarchy, encryption, ZIP64, multidisk, and local/central consistency guards with typed assertions.

The FFI performs generic import replacement only after decode and editor construction and encodes exports from a coherent cloned document outside the lock. Qt preserves the complete active projection when an open/import decode fails, but general edit/history/proposal paths still perform separate playback navigation before the operation is known to succeed.

The release build gates configure, build, and install on generated notices, source offer, and a deterministic bundle with an internal checksum manifest. `SOURCE_OFFER.md` is stable across the unborn-to-first-commit transition because dynamic Git identity lives only in `.redrob-source-identity.json`; raw repository-local origin lookup avoids global `insteadOf` rewrite leakage. The dependency bundler does not prove that the unpacked registry tree it archives matches the verified package archive.

## Qt playback navigation sits outside rejected action transactions

`EditorBridge::executeCommand` calls `stopPlayback()` and ignores its result before sending the command to `redrob_editor_execute_json` (`native/qt/EditorBridge.cpp:453-472`). When playback is active, stopping it sets `playing=false`, advances generation, and refreshes the projection; a malformed or semantically invalid command can then fail after that state change. `executeHistoryAction` has the same ordering, so an unavailable undo/redo can stop playback before reporting failure (`native/qt/EditorBridge.cpp:480-505`). This is **confirmed** from the bridge and core navigation paths.

`applyProposal` stops playback before comparing the proposal's captured generation and document epoch (`native/qt/EditorBridge.cpp:2001-2007`). Since stopping active playback increments generation, a proposal captured at the current generation necessarily becomes stale during its own Apply attempt; the action is rejected after playback has changed. The QML Apply control remains enabled during playback (`qml/Main.qml:1984-1988`), and smoke coverage does not exercise rejected commands, unavailable history, or proposal Apply in this state.

Move validation/freshness checks ahead of playback mutation and make successful edit-plus-stop behavior one atomic core/FFI operation, or explicitly stop playback before proposal capture and disable these actions until the synchronized stopped generation is visible. Add playback-active regressions that assert playing, generation, current frame, history, project identity, and render projection are unchanged for every rejected route, plus a successful current-generation proposal Apply.

## Registry archives and bundled dependency trees are not cryptographically connected

`registry_source_records` verifies the cached `.crate` at `archive_path` against the `Cargo.lock` package checksum, but then walks `package_root` and archives those separately unpacked files (`tools/generate_distribution_artifacts.py:400-428`). For normal Cargo registry cache roots there is no `.cargo-checksum.json` check—the per-file comparison only runs when the source already resides under this repository's `vendor/` directory. The generator creates a new `.cargo-checksum.json` from whatever bytes are in `package_root` while retaining the original package checksum.

This is **confirmed** by the implementation and current Cargo cache layout. A modified unpacked dependency would be accepted into `vendor/` and the notice corpus even when it no longer corresponds to the verified archive, contradicting `SOURCE_OFFER.md` claims that the bundle contains exact checksum-verified registry sources and verifies each package against Cargo checksum metadata.

Build each vendored package directly from the verified `.crate` payload, or compare every unpacked path and byte against that archive before using `package_root` for source or notices. Reject missing, extra, type-changed, or content-changed entries, then add a test that tampers with an unpacked file while leaving the cached archive intact and confirms generation fails.

## Stable tracked offer and generation-time source identity

`generate_source_manifest` contains no branch, commit, or configured-origin values, so the first commit does not churn tracked `SOURCE_OFFER.md`. `render_source_bundle` writes those dynamic values to bundle-only `.redrob-source-identity.json`: the current unborn tree records branch `feat/initial-editor`, an empty commit, public origin `https://github.com/redrob-labs/redrob-graphics.git`, and the declared repository. Once `HEAD` exists, `git rev-parse --verify HEAD` supplies the actual commit; archived bundles retain identity as a fallback outside a Git checkout.

The origin lookup uses `git config --local --get remote.origin.url`, which returned the public repository even though `git remote get-url origin` is rewritten to the sandbox gateway by global `url.*.insteadOf`. The generated source manifest checksum stayed `09aaadf250104045905dcba85197d40494125d5ee18e9ddb676853424d732273`, and all 9,453 current bundle files matched `SOURCE_BUNDLE_SHA256SUMS`.

## Validation evidence and remaining blind spots

Independent validation passed `cargo fmt --all -- --check`, Clippy over the workspace/all targets/all features with warnings denied, all 177 Rust tests, and the Qt 6.12 Release CTest suite 4/4. Installation placed the executable, GPL license, complete generated notices, stable source offer, and corresponding-source archive; generated artifact checks and internal bundle checksums passed.

Not tested: playback-active rejected action paths and tampering of the unpacked Cargo registry source tree while its cached `.crate` remains valid.
