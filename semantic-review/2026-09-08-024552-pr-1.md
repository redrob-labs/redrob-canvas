# Sparse raster animation timeline with native Qt playback

This change adds stable frame CRUD, sparse per-frame raster cels, authoritative FPS metadata, history-neutral navigation, Agent timeline proposals, owned/coherent FFI projections, and a native Qt timeline panel. Blank frames stay allocation-free until raster mutation, while duplicate cels share clone-on-write storage through the transactional command bus. Several authority and invalidation contracts break at serialization, Agent numeric, and Qt notification boundaries. **Watch for: (confirmed) loaded v2 projects can retain frame durations that disagree with FPS; (confirmed) starting playback outside its range switches the frame without canvas invalidation; (confirmed) same-count frame moves can leave QML boundary controls stale; (confirmed) Agent FPS decoding can round a just-over-limit input into range; and (confirmed) required timer and boundary regressions are incomplete.**

**Verdict**: NEEDS_CHANGES

## High-level view

The core resolves rendering by stable current-frame ID. Missing cels remain transparent, raster edits materialize only the active node/current frame after budget preflight, duplicates share `RasterBytes`, and frame mutations use clone/apply/validate/commit history transactions.

FPS drives normalized frame duration and the Qt timer interval. **Confirmed:** project validation checks only that each serialized duration is nonzero and bounded, so persisted frame metadata can disagree with the playback clock.

Navigation advances generation without touching undo/redo. **Confirmed:** starting playback can normalize an out-of-range current frame to the range start while reporting that the canvas did not change.

Agent timeline calls become generation-bound inert proposals with deterministic IDs from immutable proposal context. **Confirmed:** the FPS DTO narrows untrusted JSON to `f32` before checking the upper bound, allowing values immediately above 240 to round down and pass.

Qt cross-checks coherent document/layer/timeline metadata against render and selection generations before publication. **Confirmed:** its timeline detector compares current frame ID and row count but not ordering/current index, so a same-count move can reset the model without notifying QML properties derived from `currentFrameIndex`.

The reported validation is green, and 108 Rust tests are discoverable with two CTest smoke targets. **Confirmed:** the timeline regressions do not drive an actual `QTimer` timeout or move control, and core/Agent tests omit required transactional and logical-budget boundaries.

<details><summary>Details</summary>

## Serialized frame duration can disagree with authoritative FPS

The loaded-project path does not enforce the command-side FPS invariant: `validate_timeline` accepts any `duration_ms` between 1 and `MAX_FRAME_DURATION_MS` without comparing it to `timeline_frame_duration_ms(timeline.fps)` (`crates/redrob-core/src/document.rs:2065-2082`). A v2 document with `fps: 24` and `duration_ms: 100` passes `load_project`, is exposed unchanged through FFI/Qt, and can be saved again while the playback clock runs at roughly 42 ms. This is a **confirmed** authority violation; validate serialized durations against the derived FPS value, or normalize at a clearly defined load boundary, and add a mismatched-but-individually-valid fixture beside `crates/redrob-core/tests/editor_core.rs:1477-1485`.

## Playback activation under-reports its implicit frame switch

`Document::set_playing(true)` moves `current_frame` to `range_start` when the viewed frame lies outside the range (`crates/redrob-core/src/document.rs:1018-1032`), but `Editor::navigate` hard-codes `canvas_changed = false` for every `Navigation::SetPlaying` (`crates/redrob-core/src/editor.rs:541-544`). The ChangeSet therefore denies a canvas change even when the rendered frame changes. This is **confirmed**; derive `canvas_changed` by comparing frame IDs before and after playback-state application, with an out-of-range-start regression that also verifies generation and history neutrality.

## Agent FPS validation narrows before checking the schema boundary

`TimelineFpsArgs` deserializes `fps` directly to `f32`, then checks the narrowed value against 240 (`crates/redrob-ffi/src/graphics_tools.rs:878-882,1851-1855`). JSON such as `240.0000001` rounds to exactly `240.0f32` before comparison and is accepted despite exceeding the declared maximum. This is a **confirmed** strict-conversion gap; retain provider precision in an `f64` DTO, validate first, and only then convert. The same module already uses that pattern for brush size to prevent just-over-limit rounding (`crates/redrob-ffi/src/graphics_tools.rs:972-976`).

## Same-count frame moves do not notify derived Qt timeline properties

Every coherent refresh replaces `FrameModel`, but `timelineStateChanged` compares only current frame ID, row count, FPS, range IDs, loop, and playing state (`native/qt/EditorBridge.cpp:1160-1165`). Moving the current frame from index 0 to 1 keeps those values unchanged, so `timelineChanged` is not emitted (`native/qt/EditorBridge.cpp:1202-1204`). This is **confirmed** to leave `moveFrameLeftAction.enabled` and `moveFrameRightAction.enabled`, whose dependency is `currentFrameIndex`, at their pre-move boundary state. Compare ordered IDs/current index/durations or emit the timeline notification whenever the accepted frame projection changes.

## Native smoke bypasses the playback clock and frame move path

The production-QML smoke locates timeline controls and invokes add, duplicate, and delete, but never either move control. Its playback assertion calls `setPlaying(true)` and immediately calls `advancePlayback()` directly (`native/qt/main.cpp:129-205`), so it cannot demonstrate that `QTimer` fires at the FPS-derived interval or stops at the non-looping range end. This is a **confirmed** coverage gap; invoke a move action and assert reordered rows plus boundary enabled state, then allow one real timer timeout and assert tick/stop behavior before restoring deterministic screenshot state.

## Transaction and proposal boundary matrix remains incomplete

The core timeline suite covers COW detachment, one move reversal, one next-frame removal fallback, and history-neutral navigation (`crates/redrob-core/tests/timeline.rs:18-296`). It does not exercise duplicate logical-storage rejection, missing duplicate source, duplicate index/ID failures, missing removal, reversed/missing range endpoints, previous-frame fallback, or independent range endpoint clamps. The Agent test covers deterministic add replay, unknown add fields, zero FPS, last-frame removal, and one invalid range, but not duplicate, move, looping, or upper-bound precision (`crates/redrob-ffi/src/graphics_tools.rs:3492-3521`). This is a **confirmed** required-test gap; add transactional before/generation assertions for rejected core mutations and strict positive/negative conversion coverage for all seven timeline proposal tools.
