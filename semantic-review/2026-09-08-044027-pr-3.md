# Deterministic semantic pipeline still has three resource gaps

The current tree closes original findings 1–5, 8, and 9: path grammar, paintless paths, transactional core admission/stale recovery, Qt source preservation, Agent text privacy, notice delivery, and the named coverage gaps now have production-path regressions. Original finding 6 remains partially open because document-wide semantic limits still run after document allocation; finding 7 remains partially open because proposals still do not use the core’s complete candidate admission contract. A new work-accounting gap also affects fill-plus-stroke vectors.

**Watch for:** **[HIGH, confirmed]** document-wide node/semantic totals reject only after the complete `Document` has been deserialized under a 512 MiB envelope; **[HIGH, confirmed]** fresh Agent proposals can pass proposal validation but fail immediately on Apply at render-work or raster-storage limits; **[MEDIUM, confirmed]** fill-plus-stroke rasterization can perform nearly twice the advertised sample-edge visits.

**Verdict**: NEEDS_CHANGES

## High-level view

The deterministic geometry contract is coherent: open filled subpaths close, post-`Close` drawing requires a new `MoveTo`, stationary segments are no-ops, and paintless paths reject. The work limiter does not account for both edge scans when a path has fill and stroke.

Typed Add and Set commands are transactionally safe because `Editor` validates the mutated candidate before generation/history commit. Hosted proposals apply narrower semantic and aggregate checks, leaving render-topology and raster-storage failures discoverable only after approval.

Text strings and individual vector arrays have bounded serde visitors, and the encoded project is capped at 512 MiB. Node count and document-wide path/command/memory totals are still computed by `Document::validate` after derived deserialization has materialized all nodes and their individually legal arrays.

Qt receives authoritative semantic source fields and only advertises rectangles that can be reproduced without dropping optional paint. The hosted system prompt uses a separate summary without text/preview content, stale projection permits Undo and project replacement, and the exact font8x8 notice is installed with the application.

## Aggregate semantic and node limits remain post-allocation

**[HIGH, confirmed]** `load_project` checks only the 512 MiB encoded envelope before `serde_json::from_slice::<ProjectV2>` constructs the complete derived `Document`; `Document::validate` then enforces `MAX_NODES`, the one-million-command total, and the 64 MiB logical semantic budget (`crates/redrob-core/src/codec.rs:17-20,121-136`; `crates/redrob-core/src/document.rs:812-824,2105-2163`). The custom visitors cap one string, one vector’s path array, and one path’s command array, but do not carry totals across paths or nodes (`document.rs:463-535`). A project can contain many individually legal 65,536-command paths or semantic nodes, allocate them all, and only then fail `vector command complexity`, `semantic memory bytes`, or `node count`.

The 512 MiB input cap prevents the previous multi-gigabyte envelope but does not enforce the smaller model budgets before allocation; compact command JSON can materialize hundreds of megabytes of `PathCommand` values in addition to the caller-owned input. Decode `Document.nodes` with a bounded/running visitor, charging semantic usage as each node/path is accepted and stopping at the first over-limit element. Add an aggregate multi-path/multi-node decode regression rather than only direct `VectorContent` exact/one-over tests.

## Hosted proposals still use a narrower admission contract than Apply

**[HIGH, confirmed]** Add/Set proposal conversion calls semantic content preflight plus replacement arithmetic, and deterministic IDs probe existing nodes (`crates/redrob-ffi/src/graphics_tools.rs:1985-2053,2380-2470`). `ProposalContext` does not retain visibility/opacity topology or stored-raster usage, while the rasterize branch checks only that the target is semantic (`graphics_tools.rs:1317-1395,2472-2490`). Core Apply subsequently validates the whole candidate and can reject render-work or storage limits (`crates/redrob-core/src/editor.rs:566-580`; `crates/redrob-core/src/document.rs:1360-1378`; `crates/redrob-core/src/render.rs:28-86`).

A valid 1,024² document at the tested 256 Mi render-visit boundary can receive an off-canvas AddText proposal: semantic work and aggregate payload checks pass, but Apply adds two render operations and returns `RenderWorkLimitExceeded`. Likewise, a fresh Rasterize proposal is accepted when stored raster bytes leave less than one current-frame cel, then Apply returns `stored raster bytes`. This contradicts the later audit’s claim that accepted proposals remain applicable to their immutable snapshot. Run proposed commands through a non-mutating clone of the authoritative `Editor`, or extend shared core admission to cover every candidate-level limit; add proposal-then-Apply fixtures for both boundaries.

## Fill-plus-stroke paths undercount sample-edge work

**[MEDIUM, confirmed]** `prepare_vector` charges `pixels × 16 × edges` regardless of paint combination (`crates/redrob-core/src/semantic.rs:264-307`). Rasterization scans all edges for winding when fill is present and can scan all edges again for stroke distance when no edge is near a sample (`semantic.rs:498-524,539-556`). A fill-plus-stroke path near the 256 Mi sample-edge ceiling can therefore be admitted while performing nearly 512 Mi edge checks.

Charge one edge traversal for each enabled paint branch, with checked arithmetic, or use a combined traversal whose upper bound matches the accounting. Add exact-boundary tests for fill-only, stroke-only, and fill-plus-stroke paths so `MAX_SEMANTIC_SAMPLE_EDGE_VISITS` describes worst-case executed work.
