# Checksum-anchored Cargo registry source validation

The distribution generator now treats each checksum-verified cached `.crate` as the authoritative dependency source while proving Cargo’s unpacked registry tree is an exact mirror. Archive members are parsed in memory under strict path, root, type, duplicate, and conflict rules; the unpacked tree is rejected on any path, type, content, or empty-directory difference. Notices and source-bundle vendor records use captured archive bytes, closing the prior verify-then-reread gap while preserving the already-vendored checksum path. Validation runs before plain generation/check and bundle modes.

**Watch for:** No blocking correctness or security gaps remain in this registry-integrity workstream.

**Verdict**: APPROVED

## High-level view

The cached registry archive is now the trust anchor. Its digest must match `Cargo.lock` before tar parsing, and every payload entry must belong to the exact `name-version` root with a canonical relative path and a regular-file or directory type.

The unpacked Cargo cache is only a consistency surface. The generator records files and directories, ignores only a regular root `.cargo-ok`, and rejects links, special entries, or missing, extra, type-changed, byte-changed, and empty-directory differences.

Notices and bundle vendor records consume the retained snapshot rather than reopening unpacked source. Verification occurs before the mode branch, and package roots already under `vendor/` retain their `.cargo-checksum.json` validation.

The focused suite covers license tampering, tree mismatch classes, unsafe tar members, post-verification mutation, and the already-vendored path. CTest discovers it without enabling Qt.

## Registry archives become the authoritative dependency snapshot

`registry_archive_snapshot` hashes the complete archive before opening its tar payload (`tools/generate_distribution_artifacts.py:151-161`). `archive_member_path` rejects NULs, backslashes, absolute paths, empty/dot/dot-dot components, and roots other than exact `name-version` (`tools/generate_distribution_artifacts.py:132-148`). Parsing accepts only regular files and directories, rejects duplicate canonical names and both file/directory-conflict orderings, and captures file bytes plus explicit and implicit directories without disk extraction (`tools/generate_distribution_artifacts.py:162-215`).

Malformed or checksum-divergent content therefore fails closed before reaching an artifact. Capturing directories also detects removal or injection of empty directories that byte-only file comparison would miss.

## The unpacked registry tree is checked but never trusted for output

`unpacked_registry_snapshot` walks with `lstat`, accepts only directories and regular files, and limits the Cargo marker exception to root `.cargo-ok` (`tools/generate_distribution_artifacts.py:218-241`). `compare_registry_snapshots` checks type, missing, extra, and content differences over the file-and-directory namespace (`tools/generate_distribution_artifacts.py:244-287`). Normal registry caches retain the verified archive snapshot after comparison; package roots under repository `vendor/` keep the existing vendored checksum flow (`tools/generate_distribution_artifacts.py:312-351`).

Notice selection and bundle checksum/source records use `snapshot.files` (`tools/generate_distribution_artifacts.py:356-405`, `tools/generate_distribution_artifacts.py:634-667`). Later changes to Cargo’s unpacked directory cannot substitute bytes after verification.

## Registry validation gates every generator mode

The entry point verifies registry sources before generating notices and before branching among plain and source-bundle operations (`tools/generate_distribution_artifacts.py:756-767`). Plain artifact operations therefore fail on a compromised registry package even when no bundle is requested.

The 16 regressions cover the required mismatch and unsafe-archive classes, archive-authoritative reuse, and the vendored checksum path (`tools/tests/test_generate_distribution_artifacts.py:124-282`). CMake registers discovery through the selected Python interpreter whenever testing is enabled (`native/CMakeLists.txt:12-21`).
