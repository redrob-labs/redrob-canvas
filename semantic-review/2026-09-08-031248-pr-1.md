# Timeline approval boundary, bounded frame IDs, and loop playback regressions

이 재검수는 직전 리뷰의 세 지적을 닫는 변경을 중심으로 승인 경계, frame ID 할당 종료성, loop playback 계약을 다시 추적했다. Proposal Apply는 재생을 먼저 중지하고 coherent projection을 갱신한 뒤 generation/document epoch를 비교해 stale command·undo·redo를 공통 차단한다. Qt frame ID 할당은 10,000개에서 즉시 실패하고 32회 random 시도 뒤 wrap-safe bounded probe로 전환되며, loop end는 range start로 돌아가면서 playing과 history 상태를 유지한다. 기존 sparse cel, transactional frame CRUD, FPS-derived duration, range ordering, history-neutral navigation, coherent snapshot 불변식도 검증을 통과했다. **Watch for: 차단할 concern 없음; 직전 세 지적은 모두 코드와 production-path regression으로 확인되어 닫혔다.**

**Verdict**: APPROVED

## High-level view

Apply는 queue entry를 조회한 뒤 playback을 동기적으로 멈추고 projection refresh 성공 여부를 확인한다. Stop 결과의 generation과 document epoch가 proposal base와 같을 때만 action을 분기하므로 stop 이전 승인 상태는 command·undo·redo로 넘어가지 않는다.

Frame ID 선택은 core의 10,000-frame 상한과 Qt fast-fail을 맞추고, random collision이 32회 반복되면 deterministic successor probe로 전환한다. 마지막 candidate 다음부터 unsigned wrap을 허용해 점유 ID 수보다 하나 많은 후보를 확인하므로 off-by-one 없이 종료한다.

Loop playback은 range end에서 range start로 이동하면서 playing을 유지하고 generation만 한 번 전진시킨다. Core와 production Qt smoke가 current frame, playing, generation, undo/redo 보존을 함께 검증하며 non-loop timer stop도 계속 통과한다.

## Playback stop 뒤에 다시 세워진 proposal freshness 경계

`EditorBridge::applyProposal`은 queue lookup 뒤 `stopPlayback()`을 호출하고, stop 과정에서 projection이 stale해졌는지도 확인한 다음 `baseGeneration`과 `baseDocumentEpoch`를 비교한다 (`native/qt/EditorBridge.cpp:1569-1607`). 검사는 action type 분기보다 앞에 있어 command·undo·redo에 동일하게 적용된다.

```text
lookup queued proposal
  -> stop playback
       -> core navigation increments generation
       -> coherent refresh publishes stopped state
  -> compare base generation + document epoch
       mismatch: retain proposal, reject action
       match: dispatch command / undo / redo
```

Stop 중 snapshot capture가 실패하면 retry refresh와 `m_projectionStale`이 설정되고 Apply는 mutation 전에 중단된다. Stop과 freshness 검사 사이에는 event-loop pumping이 없고 timer callback과 Apply는 같은 Qt object thread에서 순차 실행된다. Refresh signal에서 동기 mutation이 발생해도 signal emission이 freshness 비교보다 먼저 끝나 갱신된 generation에 걸리며, freshness 검사와 dispatch 사이에는 signal이나 비동기 대기가 없다. Dispatch helper의 두 번째 `stopPlayback()`은 이미 stopped인 상태에서 timer만 정지한다.

Native smoke는 실제 `enqueueProposal`로 FPS command를 재생 중 queue에 넣고 `applyProposal`을 호출해 playback만 멈추고 generation이 하나 증가하며 FPS와 undo/redo가 바뀌지 않는지 확인한다 (`native/qt/main.cpp:268-288`). Stale proposal은 queue에 남아 명시적으로 reject할 수 있고 성공한 action만 제거되는 정책도 유지된다 (`ProposalModel.cpp:67-101`; `EditorBridge.cpp:1602-1607`).

## 32회 collision 뒤 wrap-safe로 끝나는 FrameIdAllocator

Allocator는 frame 수가 10,000 이상이면 generator를 호출하지 않고 실패하고, 그 아래에서는 32개의 random candidate 뒤 마지막 candidate의 successor부터 deterministic probe를 시작한다 (`native/qt/FrameIdAllocator.cpp:7-28`; `FrameIdAllocator.h:10-15`). Qt add/duplicate도 model count fast-fail과 같은 helper를 공유한다 (`EditorBridge.cpp:455-486`).

`probe <= occupied.size()`는 N개의 점유 ID에 대해 N+1개의 연속 successor를 검사한다. Unsigned wrap으로 `UINT32_MAX -> 0`도 정의되며, N+1 후보 중 하나는 반드시 비어 있다. ID 0은 유효한 stable ID라 비어 있으면 반환하고 점유됐으면 다음 값으로 진행하는 계약도 일치한다.

Native smoke는 32회 반복 collision 뒤 fallback, `UINT32_MAX`와 0을 넘는 wrap, 빈 0 선택, 10,000개에서 generator 미호출 fast-fail을 검증한다 (`native/qt/main.cpp:21-50`). Helper는 production executable에 링크되고 두 smoke의 선행 assertion으로 실행된다 (`native/qt/CMakeLists.txt:40-48`; `main.cpp:372-383`).

## Range end wrap의 playing 및 history-neutral 계약

Core loop branch는 range end에서 `range_start`로 이동하고 playing을 유지한다 (`crates/redrob-core/src/document.rs:1020-1058`). Navigation은 validate 뒤 generation을 한 번 증가시키되 history stack을 변경하지 않는다 (`crates/redrob-core/src/editor.rs:531-563`). 새 core regression은 current, playing, generation +1, canUndo/canRedo 보존과 canvas/timeline/navigation invalidation을 함께 고정한다 (`crates/redrob-core/tests/timeline.rs:272-315`).

Production Qt smoke도 `setPlaying`과 `advancePlayback`을 통해 같은 wrap과 history 보존을 확인한다 (`native/qt/main.cpp:243-258`). Timer timeout은 같은 `advancePlayback`을 호출하며 non-loop end에서 projected playing=false를 받으면 정지한다 (`EditorBridge.cpp:108-119,563-596`). Loop tick은 playing=true projection을 유지하고 proposal Apply는 timer를 먼저 정지시킨 뒤 stopped projection을 publish한다.

## 기존 타임라인 불변식의 보존

Core는 add/duplicate에서 `MAX_FRAMES`, stable ID 중복, insertion index, logical cel storage를 commit 전에 검사한다. 기존 regressions가 remove fallback, range clamp, range-crossing move rejection, FPS-authoritative duration, sparse read/materialization, duplicate COW detach를 계속 다룬다. `validate_timeline`도 1..=10,000 frame, unique IDs, current/range membership와 order, bounded FPS, FPS-derived duration을 load와 command commit에서 재확인한다 (`crates/redrob-core/src/document.rs:2065-2111`).

Navigation의 generation/history 분리, undo/redo의 viewed-frame 보존과 playback stop, FFI coherent generation 및 owned-output reset, Qt state/render/selection publication gating도 기존 테스트를 통과했다. Stale projection에서는 Apply가 차단되고 retry timer만 projection을 복구한다.

검증 결과는 `cargo test --workspace --all-targets` 114 tests, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check`, Qt 6.12 Release build, CTest `redrob_native_smoke`와 `redrob_minimal_platform_smoke` 2/2 통과다.
